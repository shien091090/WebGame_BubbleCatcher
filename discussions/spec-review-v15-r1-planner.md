## 1. 定案在規格裡的對應

v18 的七項定案(碰網即收、一批清完才出、沾錯即消失、自動換位、第 2、3 關特色、地板色相、第 3 首換曲)和數值方向裡製作人採納的細項, 規格都有對應。缺的或對不上的有三處:

- **decisions.md 本身前後不一致, 這不是規格漏寫。** 「確定要有的」v18 那條寫第 1、2 關「連續 N 小節沒有捕捉就換」、第 2 關「輪轉前 1 拍預告」。「數值方向」已改成「卡住後第 2 個拍點換位」與「預告 2 拍」, 規格照後者寫, 是對的。建議 decisions 原句後補「(數值方向 v18 取代: 卡住成立後嚴格晚於該刻的第 2 個拍點換位; 輪轉預告 2 拍)」。
- **telemetry.md「驗證指標」開頭還是舊的驗證問題**(清場成就點), 也跟規格待定 19「已結案」對不上。改為:
  > 驗證問題: 隨機換位換條件的網能不能帶來短時間內快速判斷的忙碌刺激; 一批清完才出下一批後, 畫面是否不再花亂、每一批都是一個清楚的小循環, 同時不產生等待空檔(判準見「第二句判準」); 加入拍子與踩拍回血後, 玩家會不會主動對拍並因此更爽; 三首歌三關、拍速漸進且每關換整套風格, 能不能讓玩家覺得每一關都不一樣而想撐到下一首。
- **「第 3 關崩盤」的場上氣泡數門檻 ≥ 4**: telemetry 寫「待數值確認」, 規格待定沒有這一條。補待定 21:
  > 21. 第 3 關崩盤的場上氣泡數門檻: 待數值。原因: 一批制下最多 6 顆, 原門檻 ≥ 7 不可能成立, telemetry 暫用 ≥ 4

## 2. 規則矛盾與沒定義的情況

**碰網判定與拖曳路徑**
- **沒定義: 網亮起那一刻, 拖曳中的氣泡已經壓在新亮邊上。** 主要發生在第 3 關: 跳位預告會先顯示目標邊, 玩家把對色的氣泡先停在目標邊外側等它亮。規則只寫「與線段相交或中心進入外側」, 這顆是「已經在裡面」, 算不算碰網沒寫。跳位都落在拍點上, 所以這個情況直接關係到送進網算不算踩拍。兩案:
  - A 案(建議): 照「碰到就算」的承諾, 亮起那一刻就判碰網。代價是送進網會必然踩拍, 會灌高第三題的讀數, 所以要另外標記、從讀數裡排除。規格「碰網判定」加:
    > 亮網換位(捕捉輪替以外: 自動換位、第 3 關跳位)那一刻, 拖曳中的氣泡若已與新亮邊線段相交或中心已在新亮邊外側 → 該刻即判碰網, 碰網時刻 = 換位那一刻; 照常判送進網節點與踩拍。

    telemetry 碰網事件加欄位「是否為換位當下即判」, 第三題「時間差集中」「在對拍」都排除這類。
  - B 案: 比照地板的「已相交」, 要先離開再碰回才算。和地板規則一致, 也不會有白送的拍點; 代價是玩家壓在亮邊上卻沒收, 違背「碰到就算」的體感。
- **沒定義: 同一幀裡, 早於拍點的那段路徑要拿換位前還是換位後的網判。** 在待定 8 原則句末補:
  > 第 3 關跳位、第 1、2 關自動換位那一幀, 本幀路徑一律用變化後的亮網判(含路徑上早於拍點的部分); 節點時刻仍取路徑上實際相交的那一刻。

**沾錯即消失與自動換位**
- 無矛盾。拖曳途中條件只會被自動換位改掉, 而卡住時場上不會有透明圓, 所以不會出現「拖的途中網換了色, 害這顆沾錯」。第 3 關跳位只換位置, 卡住時才連條件一起換, 同理成立。

**一批清完才出與換關 / 關末**
- 規則閉合。只有體驗小點: 本批在第 139.x 拍清完時下一批排在第 141 拍, 照常出, 4~5 顆會在 1~2 拍內被換關清掉。本版建議不改; telemetry「換關清掉」加一欄「該批冒出到關末的拍數」來觀察。

**第 2 關輪轉、第 3 關跳位和其他事件同一刻發生**
- **第 2 關地板位置公式在預備拍會算錯。** 關內第 −4 ~ −1 拍時 ⌊k ÷ 8⌋ = −1。改為:
  > 任一時刻地板 ID 所在的角度 = 版位表第 2 關欄的角度 + 60° × ⌊max(0, 關內拍序號) ÷ 8⌋
- **第 2 關關末前的輪轉預告沒寫清楚。** 第 160 拍不輪轉, 補:
  > 第 158、159 拍不顯示輪轉預告。
- **第 3 關「預告中捕捉 → 該拍不跳」會拉長卡住。** 最長約 9 拍(約 4.2 秒), 比待定 11 寫的約 3.7 秒長。待定 11 改為「卡住最長約 9 拍(預告中捕捉後立即卡住時, 約 4.2 秒)」。要不要在這種情況把第 k 拍的跳位保留下來, 留給數值判斷。
- 小矛盾: 範圍邊界「不做: 網依時間倒數換網」跟第 3 關按小節跳位字面上衝突。改為:
  > 網依倒數計時換網(第 3 關依小節跳位且有預告, 不在此限)

## 3. 操作

足夠支撐核心循環, 也只用滑鼠一種輸入。按下、拖曳、擦過地板、碰網涵蓋「看網 → 規劃 → 執行」; 碰網即收也讓觸控板玩家不必在網上精準放手。八邊形四周的亮邊在拖曳範圍內都碰得到。唯一的摩擦是碰網後要先放開左鍵才能抓下一顆(待定 13), 已經有埋點在看, 本版不動。

## 4. 「Demo 要驗證的問題」驗不驗得到

- 第一題(忙碌刺激): 驗得到。
- 第二題(不花亂、清楚的小循環、不產生等待空檔): 只驗得到「不等待」。建議 telemetry 加一張「第二句判準」:
  - 等待空檔: 每批「批間等待 + 首按延遲」的中位數與占存活比例。門檻由數值給, 方向是批間等待中位 ≤ 1.5 拍。
  - 清楚的小循環(描述用): 每批過期顆數為 0 的批占比; 同一批內抓取順序和陣型出場順序的一致率。
  - 花亂(描述用): 老闆原話裡是否自己提到畫面亂或清楚。
- 第三題(會不會主動對拍): 送進網時刻改成碰網後「時間差集中」還沒重核(待定 15)。「感受」靠老闆自己提到拍子, 自己提到的機率低, 建議標成「低樣本, 僅參考」。A 案的換位當下碰網要排除在讀數外。
- 第四題(每一關都不一樣): 「新鮮不變迷失」會被關卡特色本身干擾。建議門檻改為「增幅扣除數值預估的特色成本後 ≤ 15%」, 第 3 關另報「扣掉跳位次數 × 0.08 秒」的版本; 預估值請數值補。
