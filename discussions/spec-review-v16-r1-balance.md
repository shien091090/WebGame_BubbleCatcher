# 數值 spec-review v16 第 1 回合(對照 decisions v20)

結論: 規格照抄 decisions v20 的部分沒有抄錯; 埋點清單全數到位。要改的在三處: telemetry「數值假設對照」有 3 列沿用舊版數字; 新的批間等待秒數只給上限且判準層級與拍數判準不一致; 第 2 關扣血後備的觸發門檻跟預測值重疊。

## 二、抄寫核對
規格與 telemetry 對照 decisions v20 皆無抄錯(第 2 關跳位、第 3 關輪轉、第 64 拍同拍、兩個後備、換位當下即判觸發、結構成本 0.19 / 0.20、分類、偏移補償、批間等待、第 3 關斜率後備、沾上窗 ±132 / ±115 / ±103 毫秒、埋點欄位)。

小瑕疵: 核心循環第 5 步「隔 2 拍左右出下一批」實際是 1~2 拍、平均約 1.3 拍; 「沒修約 183 / 231 / 260 秒」decisions 沒有, 推算自洽但來源請確認。

「數值假設對照」有錯的:
1. 每秒收入列: 還是舊分類名與舊數字。應依踩拍分類: 第 2 關收入(bug 修好、對調後)不踩拍型約 4.2、半數型約 4.8~5.0; 第 3 關開頭約 3.8 / 4.8 / 5.6。
2. 難度斜率列: 「約第 38 秒滿血」錯(實測 15~23 秒); 「半數型第 1 關 +1.7~2.1」錯(實測 +2.5~2.7, +1.7 是不踩拍型); 第 2 關「約 0.0」偏樂觀, 依實測 −0.12。
3. 指標 5 預估列: 依本版模型重算 —— 不踩拍型首次血量 ≤ 40 第 163 秒、占比約 15%; 半數型第 225 秒、約 8%; 大部分型第 254 秒、約 7%(舊列「約 26%」已不成立)。
4. 第 3 關輪轉列自相矛盾: 「撞上約 55%、每次 0.29 秒」相乘是 0.16, 列內寫 0.145; 每次 0.29 與結構成本 0.20 差 45%。建議改每次約 0.20 秒、每張網多約 0.11 秒。

其餘換算對得上。

### 平均批間等待秒數(0.90 / 0.78 / 0.70)
換算對, 但只換了上限, 下限 1.1 拍沒換(應 0.66 / 0.57 / 0.52); 拍數判準是「每局平均」, 秒數寫成「各關」, 會互相打架(223754 整局 1.38 拍過關, 但第 3 關 1.63 拍 = 0.77 秒 > 0.70)。另批間空白占比「第 2 關起 ≤ 12%」實測 9.8~12.5%, 已在臨界上。

### 各關淨血拆解換算口徑
時間換血量應乘「該關非滿血期間每秒收入(溢出前應得)」; 特色沾錯用扣血 3 加總會低估約 2.7 倍, 應用「沾錯實際成本」; 第 2 關跳位結構上不會造成沾錯, 特色沾錯應恆為 0; bug 時間建議設上限為該關一項條件網在場時間中位。
