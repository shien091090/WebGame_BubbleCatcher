# 音效說明(對應 spec v13「音效清單」)

## 聲音風格

明亮的 8-bit 晶片音電子節拍: 150 BPM 四拍大鼓打底的晶片音樂, 回饋音用清脆的玻璃叮聲與合成器掃頻, 清場與危險用 8-bit 短樂句。

## 事件表

所有一次性音效用 `Sound.play(name, opts)`; `opts` 可省略。共通欄位 `opts.x`(0~1280, 動作發生處的 x 座標, 可省略): 給了就依左右位置做輕微立體聲定位。

| 事件名 | 對應 spec 音效清單 | 何時呼叫 | opts 欄位 | 素材 | 相對音量 | 循環 |
|---|---|---|---|---|---|---|
| `countIn` | 預備拍 | 預備拍第 −4、−3、−2、−1 拍各一次(拍點那一刻) | `left`: 還剩幾拍開始, 依序傳 4、3、2、1; 音高 do→re→mi→so 逐拍升高, 最後一拍(`left: 1`)最高也最響 | count_in_pluck(Kenney pluck_002) | 0.8 | 否 |
| `onBeat` | 踩拍 | 計次節點踩拍那一刻: 抓起在判成拖曳那一刻; 第一次沾上、第二次沾上、送進網在動作那一刻。沒踩拍不呼叫 | `step`(可省略): 這是該顆第幾個踩拍的節點(1~4), 越後面音越高, 用來帶出「一路對上」的感覺; `x` | on_beat_glass(Kenney glass_001) | 1.0(全場最亮的短音) | 否 |
| `beatChain` | 整串踩拍 | 整串踩拍成立的捕捉那一刻 | `x` | beat_chain_powerup(Kenney powerUp9)+ 疊兩層高八度 on_beat_glass | 0.9 + 疊層 | 否 |
| `catch` | 捕捉 | 捕捉成功那一刻(不論有沒有踩拍) | `x` | catch_confirm(Kenney confirmation_001) | 0.45 | 否 |
| `netSwap` | 網換位 | 新網亮起那一刻(與捕捉同一幀) | `x`: 新網的 x | net_swap_phaser_up(Kenney phaserUp7) | 0.4 | 否 |
| `expire` | 過期 | 氣泡壽命歸零消失那一刻; 同幀多顆可每顆各呼叫一次 | `x` | expire_phaser_down(Kenney phaserDown3) | 0.5 | 否 |
| `clear` | 清場 | 清場成立那一刻 | 無 | clear_jingle(Kenney 8-bit jingles_NES12, 上行六音) | 0.75 | 否 |
| `danger` | 血量危險 | 血量降到 ≤ 40 進入危險狀態那一刻, 一次(解除前不再呼叫) | 無 | danger_jingle(Kenney 8-bit jingles_NES13, 兩音顫動) | 0.65 | 否 |
| 背景音樂 `main` | 背景音樂 | 見下節 | 見下節 | 程式產生(Web Audio 合成) | 0.45 | 是 |

不出聲(不要呼叫): 卡死縮短、沒踩拍的節點、條件不符彈回、放在其他位置彈回。

素材格式: 短音效以 16-bit PCM base64 內嵌在 sound.js, `init()` 時同步填進 AudioBuffer, 用 Web Audio 播放(起音不受載入延遲影響)。瀏覽器沒有 Web Audio 時退回 `audio/assets/*.mp3` 的 4 複本播放池; 此時背景音樂不播。

## 背景音樂與拍子時鐘

**背景音樂為什麼是程式產生**: 搜過 OpenGameArt(CC0 晶片音樂, 標示的拍速多為 129 / 140 BPM, 沒有可驗證的 150 BPM 且起拍在第一小節的循環)與 Pixabay(有標 150 BPM 的素材, 但頁面對下載工具回 403、拍速與循環點無法驗證), 規格要求拍速與循環點精準, 改由 sound.js 合成。

**保證的事**:
- 150 BPM、4/4, 8 小節(32 拍、12.8 秒)一個循環; 循環長度在 44.1k / 48k 取樣率下都是整數個取樣點, 用 Web Audio 的無縫循環播放, 接縫不斷拍、不偏移; 尾音繞回開頭合成, 接縫處沒有空白
- 歌曲第 0 秒 = 第一小節第一拍 = 時鐘第 −4 拍(預備拍第一拍)。歌曲位置 = ((時鐘拍 + 4) × 0.4 秒) 取 12.8 秒的餘數
- 每一拍一記大鼓(全曲最響的成分), 小鼓輕打在第 2、4 拍上, 反拍只有很輕的 hi-hat; 低音與旋律音都起在拍上。量測: 拍上能量平均比反拍高約 5.6 dB, 每一個拍上都比任何反拍響; 自相關量得週期 400 毫秒 = 150.0 BPM
- 音樂預設做「輸出延遲補償」: 對齊時把音樂往前推 `getOutputLatency()` 秒, 讓玩家**聽到**的拍子對齊時鐘拍點

**介面**(時鐘拍 `beat` = 存活秒數 ÷ 0.4, 可為小數; 預備拍中為 −4 ~ 0 的負值):

| 介面 | 用途 | 何時呼叫 |
|---|---|---|
| `Sound.playMusic('main')` | 從歌曲開頭(= 時鐘第 −4 拍)開始播, 循環 | 每局(含重開、再玩一次)預備拍第 −4 拍那一刻 |
| `Sound.playMusic('main', { beat })` | 讓音樂「此刻」對到時鐘拍 `beat` 開始播 | 呼叫時鐘已走過 −4 拍一點點時, 傳當下的時鐘拍較準 |
| `Sound.syncMusic(beat, toleranceSec?)` | 傳入當下時鐘拍; 音樂偏離超過容許值(預設 0.04 秒)就把音樂對回時鐘。回傳偏差秒數(音樂 − 時鐘, 正值 = 音樂超前) | 局中(含預備拍)每幀或每拍呼叫; 偏差在容許內什麼都不做, 很便宜 |
| `Sound.pauseMusic()` | 停下音樂(時鐘由 RD 凍結) | 暫停那一刻 |
| `Sound.resumeMusic(beat)` | 從時鐘拍 `beat` 對應的位置接著播 | 恢復那一刻, 傳恢復時的時鐘拍(= 暫停時的時鐘拍) |
| `Sound.seekMusic(beat)` | 同 `resumeMusic`, 強制立刻對到 `beat` | 需要手動對齊時 |
| `Sound.stopMusic()` | 淡出並停止 | 局結束、離開遊戲畫面(結束畫面、回標題)時 |
| `Sound.getOutputLatency()` | 回傳音訊輸出延遲(秒) = outputLatency + baseLatency; init 前回 0 | 給判定偏移補償與埋點參考 |
| `Sound.getMusicBeat()` | 目前「聽到的」音樂對應的時鐘拍; 沒在播回 null | 埋點或除錯 |
| `Sound.setMusicLatencyCompensation(bool)` | 開關音樂的輸出延遲補償(預設開) | 通常不用動; 若 RD 決定自己在判定端補延遲, 關掉以免補兩次 |
| `Sound.BPM` / `Sound.BEAT_SEC` / `Sound.LOOP_BEATS` / `Sound.SONG_START_BEAT` | 150 / 0.4 / 32 / −4 | 常數 |

**權威**: 時鐘以存活時間為準, 音樂永遠跟著時鐘走; sound.js 不提供時鐘, 也不會反過來改時鐘。

**靜音**: `setMuted(true)` 只把總音量降到 0, 音樂照樣在背景走(對齊不會跑掉), 取消靜音時立刻是對的位置。靜音狀態的本機紀錄由 RD 做(載入時呼叫 `setMuted(記錄值)`, init 前呼叫也有效)。

**其他**:
- `init()` 之前的 `play`、`playMusic` 一律靜默丟棄; 開局按「開始」那一下若同時是 init, 先 `init()` 再 `playMusic`
- 剛 init 的 AudioContext 可能晚幾十毫秒才真正出聲, 第一個 `syncMusic` 會把差距對回來

## 同時觸發的處理

| 同一刻可能一起發生 | 處理 |
|---|---|
| 捕捉 + 網換位(必定同幀) | `netSwap` 若在 `catch` 之後 50 毫秒內呼叫, 自動延後 70 毫秒才響, 兩聲分開; 網換位音量最低 |
| 捕捉 + 送進網踩拍(`onBeat`) | 兩聲都響; 踩拍(1.0)明顯壓過捕捉(0.45) |
| 捕捉 + 送進網踩拍 + 整串(`beatChain`) | 三個都照呼叫, 順序不拘: 整串內建一層高八度叮聲, 若 60 毫秒內已響過 `onBeat` 就省掉這層; 若 `beatChain` 先響, 隨後 60 毫秒內的 `onBeat` 自動略過 |
| 捕捉 + 清場(最後一顆在空檔中被收) | 都響; 清場是樂句(0.8 秒), 捕捉音短且小, 不互相蓋 |
| 過期 + 清場(靠過期清場) | 都響 |
| 過期 + 血量危險 | 都響; 危險音量較大, 過期只是短下滑音 |
| 同幀多顆過期 | 每顆各呼叫一次也可, 會疊成較厚的一聲 |
| 血量危險 | 一秒內重複呼叫只響第一次(保險; 規則上本來只響一次) |
| 預備拍 + 背景音樂 | 預備拍叮聲疊在音樂第一小節的拍上, 同步 |

響度由大到小: 整串 > 踩拍 > 清場 > 預備拍 > 危險 > 過期 > 捕捉 > 網換位; 背景音樂 0.45。

## 理念或經驗落實

- 即時回饋音聽起來延遲(技術, SlimeTetris round-11): 每個素材都量了「出到峰值一成的時間」, 踩拍 0 毫秒、整串 4.7 毫秒、捕捉 0.1 毫秒、網換位 3.5 毫秒、過期 10.6 毫秒、清場 / 危險 3.4 毫秒, 全部在 0.03 秒內; 全部短音效以 16-bit PCM base64 內嵌、init 時同步填進 AudioBuffer、用 Web Audio 播放, 沒有 Web Audio 才退回播放池。
