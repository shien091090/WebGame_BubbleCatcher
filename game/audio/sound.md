# 音效說明(對應 spec v20「音效清單」與「新手教學」, decisions v26 選曲; 第 2、3 關背景音樂於本版換曲)

## 聲音風格

回饋音沿用上一版的明亮晶片音與玻璃叮聲(Kenney CC0), 一個都沒換; v20 新增的兩個新手教學音也取自同一套 Kenney Interface Sounds, 音量壓得比所有遊戲回饋音低。背景音樂是使用者選定的三首電子曲: 第 1 關 Voice Over Under(明亮彈跳的合成器電子, 每拍大鼓, 由 135 放慢到 105 BPM)、第 2 關 Litany to the Datastream Goddess(80~90 年代射擊遊戲風的明快合成器舞曲, 由 128 放慢到 115 BPM)、第 3 關 Thy Steel Consumed(16-bit 射擊遊戲後期關卡風, 高音合成器加失真重吉他, 由 120 加快到 125 BPM)。後兩首同一位作者(FoxSynergy), 跟上一版的第 2、3 首同一家風格。換關提示仍用鋼鼓上行樂句。

### 量法與結果

第 1 首沿用上一版, 量法與數值見下方「第 1 首(沿用)」; 第 2、3 首是本版重做。

**時間伸縮(第 2、3 首)**: 本機這次不允許執行下載的 Rubber Band 命令列工具, 改在 Python 裡做「諧波 / 打擊分離後各自伸縮」: 先用中位數濾波把聲音分成持續音(諧波)與敲擊(打擊)兩部分, 諧波用相位鎖定的相位聲碼器(2048 點窗)、打擊用 256 點短窗疊加(敲擊的起音不被抹開), 再相加。左右聲道各自處理會讓兩聲道相位對不上(量得側聲道對中聲道從 −13 dB 漲到 −3 dB, 立體聲發散), 所以改成中 / 側聲道分開處理再還原, 量得 −13.1 → −12.3 dB(第 2 首)、−15.9 → −15.5 dB(第 3 首), 跟原曲一致。只改時間不改音高。

**BPM**: 原曲以 35~250 Hz 低頻起音擬合, 兩首都是編曲軟體輸出, 正好 128.00 / 120.00 BPM(整首 4:00.05 = 128 / 120 小節), 漂移 < 0.5 毫秒。量的是**最後的 mp3 本身**(以遊戲時鐘的拍格 0.05 秒 + k × 每拍為準, 每拍找 ±25 毫秒內最陡的 5 毫秒能量上升):

**第 1 首(沿用)**: Rubber Band 4.0.0 R3 引擎離線放慢; 擬合 104.9995 BPM、漂移 +0.16 毫秒/分、拍格對實際起音中位 +0.23 毫秒; 舊量法(35~110 Hz、5 毫秒包絡)四拍都清楚的小節 36/36, 曲首第一拍就是大鼓, 預備拍那一小節 = 原曲第 1 小節; 開頭 2 毫秒淡入、0.05 秒數位靜音、增益 +0.73 dB、超過 0.95 的峰值用 2 毫秒前瞻峰值限制壓住(約 0.23 秒的樣本)。

### 對齊規則

- 時鐘拍 `beat` = 該關的時鐘拍序號(預備拍為 −4 ~ −1, 關內第 0 拍 = 0, 可為小數)。每首歌的第 0 秒(= 音檔的 `firstBeatInFileSec`)= 該關第 −4 拍
- 歌曲位置 = (beat + 4) × 該首每拍秒數。三首超過曲長(關末之後; 第 3 首是時鐘第 192 拍之後)都不出聲, 時鐘照走
- 音樂預設做輸出延遲補償: 對齊時把音樂往前推 `getOutputLatency()` 秒, 讓玩家**聽到**的拍子對齊時鐘拍點
- 解碼器開頭填充自動校正: 解碼後比對檔內第一個聲音的位置, 差異在 0.1 秒內就自動修正

### 介面

| 介面 | 用途 | 何時呼叫 |
|---|---|---|
| `Sound.playMusic('stage1' 或 'stage2' 或 'stage3')` | 從歌曲開頭(= 該關第 −4 拍)開始播; 若前一首還在響, 前一首 0.3 秒淡出 | 開局(含重開、再玩一次)預備拍第 −4 拍那一刻播 `stage1`; 換關那一刻(新關第 −4 拍)播下一首 |
| `Sound.playMusic(name, { beat })` | 讓音樂「此刻」對到該關時鐘拍 `beat` 開始播 | 呼叫時時鐘已走過 −4 拍一點點時, 傳當下的時鐘拍較準 |
| `Sound.syncMusic(beat, toleranceSec?)` | 傳入當下時鐘拍; 音樂偏離超過容許值(預設 0.04 秒)就對回時鐘。回傳偏差秒數(音樂 − 時鐘, 正值 = 音樂超前); 曲子播完後回 0 | 局中(含預備拍)每幀或每拍呼叫; 偏差在容許內什麼都不做 |
| `Sound.pauseMusic()` | 停下音樂(時鐘由 RD 凍結) | 暫停那一刻 |
| `Sound.resumeMusic(beat)` | 從時鐘拍 `beat` 對應的位置接著播 | 恢復那一刻, 傳恢復時的時鐘拍(= 暫停時的時鐘拍) |
| `Sound.seekMusic(beat)` | 同 `resumeMusic`, 強制立刻對到 `beat` | 需要手動對齊時 |
| `Sound.stopMusic()` | 0.15 秒淡出並停止 | 局結束、離開遊戲畫面(結束畫面、回標題)時 |
| `Sound.getMusicInfo(name)` | 回傳曲子設定物件(欄位見下); 未知名稱回 null | **建拍子時鐘、算關長、算換關時刻都用它**; 頁面載入後即可呼叫, 不需要 init |
| `Sound.isMusicReady(name)` | 該首是否已解碼好 | 除錯用; 不需要等它: 解碼完成前呼叫 `playMusic`, 解完會自動從「當下應該在的位置」開始播 |
| `Sound.getOutputLatency()` | 音訊輸出延遲(秒) = outputLatency + baseLatency; init 前回 0 | 判定偏移補償與埋點參考 |
| `Sound.getMusicBeat()` | 目前「聽到的」音樂對應的時鐘拍; 沒在播回 null | 埋點或除錯 |
| `Sound.setMusicLatencyCompensation(bool)` | 開關音樂的輸出延遲補償(預設開) | 通常不用動; 若 RD 決定在判定端補延遲, 關掉以免補兩次 |
| `Sound.SONG_START_BEAT` | −4 | 常數 |

`getMusicInfo(name)` 回傳的欄位(**本版新增**的標粗):

| 欄位 | 意義 | stage1 / stage2 / stage3 |
|---|---|---|
| **`file`** | 曲檔路徑(相對 index.html) | `audio/assets/music_stage1.mp3` 等 |
| `bpm` | 實測 BPM, 時鐘用它 | 105 / 115 / 125 |
| `beatSec` | 每拍秒數 = 60 ÷ bpm | 0.5714… / 0.5217… / 0.48 |
| `bars` | 檔內小節數(含預備拍) | 37 / 41 / 49 |
| `levelBars` | 關長小節數 | 36 / 40 / 48 |
| `songStartBeat` | 歌曲第 0 秒對應的時鐘拍 | −4 |
| `lengthSec` | 歌曲長度(不含檔頭靜音) | 84.571429 / 85.565217 / 94.08 |
| **`firstBeatInFileSec`** | 第一拍(預備拍第 −4 拍)在音檔中的秒數 | 0.05 / 0.05 / 0.05 |
| **`levelStartInFileSec`** | 關內第 0 拍在音檔中的秒數 | 2.3357 / 2.1370 / 1.97 |
| `loop` | 是否循環 | false / false / false(本版起第 3 首也不循環) |
| `loopStartBeat` / `loopBeats` | 循環起點的時鐘拍 / 一輪拍數 | 三首都 null |
| `loopStartInFileSec` / `loopEndInFileSec` | 循環起訖在音檔中的秒數 | 三首都 null |

`...InFileSec` 是音檔本身的秒數(未經解碼器校正), 只供核對或退路使用; 用 `playMusic` / `syncMusic` 播放時 sound.js 已自動處理, RD 不必自己換算。

**權威**: 時鐘以關內時間為準, 音樂永遠跟著時鐘走; sound.js 不提供時鐘, 也不會反過來改時鐘。

**換關那一刻建議呼叫順序**: `play('stageChange')` → `playMusic('stage2')`(或 `stage3`)→ `play('countIn', { left: 4 })`。三首的音檔長度都剛好到關末, 換關時上一首已自然結束; 第 3 首播完那一刻就是第 3 關關末(時鐘第 192 拍)。

**靜音**: `setMuted(true)` 只把總音量降到 0, 音樂照樣在背景走(對齊不會跑掉), 取消靜音時立刻是對的位置。靜音狀態的本機紀錄由 RD 做(載入時呼叫 `setMuted(記錄值)`, init 前呼叫也有效)。

**其他**:
- `init()` 之前的 `play`、`playMusic` 一律靜默丟棄; 開局按「開始」那一下若同時是 init, 先 `init()` 再 `playMusic`
- 剛 init 的 AudioContext 可能晚幾十毫秒才真正出聲, 第一個 `syncMusic` 會把差距對回來

## 同時觸發的處理

| 同一刻可能一起發生 | 處理 |
|---|---|
| 觸發 + 光門換位(必定同幀) | `netSwap` 若在 `catch` 之後 50 毫秒內呼叫, 自動延後 70 毫秒才響, 兩聲分開; 光門換位音量最低 |
| 同一刻兩次換位(第 2 關跳位那一刻換位當下即判觸發, 接著輪替; 或自動換位與觸發同幀) | 兩次都照呼叫 `netSwap` 也可: 40 毫秒內的第二次自動略過, 只響一次 |
| 觸發 + 送進光門踩拍(`onBeat`) | 都響; 踩拍(0.85~1.0)明顯壓過觸發(0.45) |
| 觸發 + 送進光門踩拍(第 2 或 3 級)+ 整串(`beatChain`) | 都照呼叫: 踩拍那一下先出, 整串的上揚掃頻同時起、再往上跑兩個高音(0.1、0.2 秒), 聽起來是「第 N 級叮 + 一串往上衝」, 跟單獨第 3 級分得開 |
| 地板輪轉 + 染上踩拍(輪轉那一拍剛好染上)或 + 自動換位 | 都響; 輪轉是短機械「喀嚓」(兩下, 相隔 0.11 秒), 沒有音高, 跟玻璃叮聲與換位的上揚掃頻分得開 |
| 地板輪轉 + 背景音樂 | 輪轉落在第 3 首每 2 小節的第 1 拍, 喀嚓聲疊在大鼓上, 當成一下額外的打擊 |
| 沾錯消失 + 血量危險(沾錯讓血量跌破 40) | 都響; 危險樂句較大聲較長, 沾錯是 0.16 秒的短促低音錯誤聲 |
| 沾錯消失 + 過期(同幀) | 都響; 沾錯(0.4, 0.16 秒)明顯比過期(0.5, 0.42 秒下滑音)輕、短 |
| 換關 + 預備拍第 −4 拍 + 新歌開頭(必定同一刻) | 都響; 換關鋼鼓樂句 1.4 秒會蓋過前 2~3 個預備拍叮聲的時段, 但音色與音高不同, 預備拍叮聲仍聽得出; 換關音量刻意比預備拍低(0.6 對 0.8) |
| 過期 + 血量危險 | 都響; 危險音量較大, 過期只是短下滑音 |
| 同幀多顆過期 | 每顆各呼叫一次也可, 會疊成較厚的一聲 |
| 血量危險 | 一秒內重複呼叫只響第一次(保險; 規則上本來只響一次) |
| 預備拍 + 背景音樂 | 預備拍叮聲疊在歌曲第一小節的拍上, 同步; 第 1、2 首的預備拍那一小節每拍都有大鼓, 第 3 首第 2 拍沒有大鼓, 由預備拍叮聲補上 |
| 教學完成 + 觸發(+ 踩拍、整串)(階段 3「送」與階段 5「染錯」的完成就是一次觸發, 必定同幀) | 都照呼叫, 順序不拘: `tutorialDone` 若在 `catch` / `onBeat` / `beatChain` 之後 50 毫秒內呼叫, 自動延後 0.15 秒才響, 排在遊戲回饋音後面; 音量 0.3 是全表最低, 不蓋過觸發與踩拍。建議 RD 先呼叫遊戲回饋音再呼叫 `tutorialDone`(反過來就不會延後) |
| 教學完成 + 回血(階段 6)或抓起(階段 1、4) | 回血本身沒有音效、抓起不出聲, 只有 `tutorialDone` 一聲 |
| 教學提示彈出 + 其他事件 | 都響; `tutorialShow` 是 0.16 秒、約 800 Hz 的悶「啵」, 跟高亮的玻璃叮、預備拍撥弦、換位的上揚掃頻都分得開。150 毫秒內重複呼叫只響第一次 |
| 教學完成連續兩次 | 300 毫秒內重複呼叫只響第一次(保險; 規則上每階段只完成一次) |

響度由大到小: 整串 > 踩拍第 3 級 > 第 2 級 > 第 1 級 > 預備拍 ≈ 地板輪轉 > 危險 > 換關 > 過期 > 觸發 > 光門換位 > 沾錯消失 > 教學提示彈出 > 教學完成(教學完成的音色最亮, 所以音量最低, 聽感上與彈出差不多輕); 背景音樂三首統一到 −19 dBFS RMS(與上一版相同), 再乘音樂匯流排 0.7, 所以回饋音與音樂的相對大小跟上一版一樣。

## 理念或經驗落實

- 程式合成的短循環被嫌膩(品味, 本作 round-7): 三首都是現成整首曲子截段, 沒有疊合成層; 第 3 首本版起不循環。
- 精準 BPM 曲子去哪找(素材來源): 曲目由使用者選定, 不再選曲; 仍照同一套方法實測輸出檔的拍速與漂移, 三首整首累積漂移都在 1 毫秒以內。
- 背景音樂節奏感太弱、量大鼓清楚度(辨識, 本作 round-8): 調速前後都量清楚度並逐小節掃描全曲, 截取窗選無鼓小節最少的位置; 第 2 首仍有 3 小節躲不掉的無鼓過門、第 3 首多數小節第 2 拍無鼓, 已在上節寫明, 待試玩確認是否影響抓拍。
- 量清楚度時相位要用低頻找(辨識, 本作選曲調查): 選窗時相位用低頻清楚度搜尋; 最後的驗收則直接用遊戲時鐘的拍格(0.05 秒 + k × 每拍)量, 量到的就是玩家實際聽到的對齊情形。
- 低拍速又要每拍大鼓的曲子難找(辨識, 本作選曲調查): 拿快曲用保留音高的時間伸縮調到 105 / 115 / 125; 量得調速本身對大鼓清楚度影響小(第 2 首中位 −0.6 dB, 第 3 首不變)。
- 背景音樂對齊(技術): 沿用內嵌 mp3 + 離線解碼 + 開頭填充自動校正; 本版三首都不循環, 不需要循環保險段(循環程式碼保留, `loop` 設 null 即不用)。
- CC BY 音樂的署名(授權): 三首都要署名(1 首 CC BY 4.0、2 首 CC BY 3.0), 且三首都要註明已調速並截取; 署名文字在 credits.md, 遊戲畫面上第 2、3 關的署名要換掉。
- 即時回饋音延遲(技術, SlimeTetris round-11): 回饋音沿用上一版, 都已量過出聲時間並以 PCM 內嵌, 本版未動。v20 兩個教學音同樣量過(出到峰值一成都是 0 毫秒)並以 PCM 內嵌。
