# 捕泡手 美術規格(style.md)

RD 只需讀本檔。`art.js` 掛在 `window.Art`, 非 ES module。art.js 內含中文字串, `index.html` 必須有 `<meta charset="utf-8">`, 否則 file:// 下所有文字變亂碼。

本版(v10 規格, 中央圓形場地)相對 game-v8 的變動:
- 版面換成中央場地: 內圈 (640,360) 半徑 210; 周邊 8 個網槽位(距圓心 300); 6 塊區域在內圈裡半徑 140 的環上, 半徑 24、階段 5 起 20。所有座標與半徑都在 `Art.layout`, 直接讀
- **刪除 `drawWashZone`**(洗除區移除); `Art.layout` 刪除 `nets`、`gaps`、`paintR`、`shapeR`、`washR`, 改為 `slots`、`slotById`、`zoneR`、`zoneRSmall`
- `drawNet` 改寫成「網槽位」: `status` 只剩 `'off'`(不亮)/`'on'`(亮著); **新增 `lightT`、`from`**(剛亮起的換位提示); 刪除 `nextShape`、`previewT`、`introT`、`status:'preview'`(規格不預告下一張網); `color` 改為每張網各自傳(不再綁槽位); `flash:'catch'` 改為**畫在不亮的槽位上也有效**(捕捉當幀原槽位就熄滅)
- `drawPaintZone`、`drawShapeZone`: **新增 `r`**(目前生效半徑)、**`status:'shrink'`**(縮小預告)與 `shrinkTo`; 形狀與水滴符號隨半徑縮放
- `drawBubble`: `swipeKind` 刪除 `'wash'`, **新增 `'locked'`**(擦過但該項屬性已鎖定、沒變)
- `layout.stageNotice` 從頂部中央移到左上 HUD 正下方(舊位置會壓到槽 7), 函式與 state 不變
- `drawBackground`、`drawInnerRing`(只改位置與半徑)、`drawHud`、`drawStageNotice`、`drawPauseButton`、`drawPauseMenu`、`drawTitleScreen`、`drawInputSelect`、`drawEndScreen` 函式名與 state 不變
- `drawGuidePage` state 不變, 6 頁內容依 v10 guide.md 重畫

## 形狀語言

圓形為主、圓角面板、扁平填色; 有色 = 實心, 無色 = 空心灰白框; 地塊是平的(無高光), 中央放一個說明效果的符號(水滴 = 染色、空心形狀 = 賦形); 亮著的網 = 網格 + 色框 + 同色外光, 不亮 = 細灰虛線空圈; 預告中 = 虛線; 新出場 / 剛改變 = 四個白色角框。

## 理念落實

- P0 辨識度先於好看: 氣泡(高光 + 壽命環、半徑 20)、染色區(平色池 + 水滴、半徑 24)、賦形區(灰藍地面 + 空心形狀)、亮著的網(網格 + 5px 色框 + 外光、半徑 60)、不亮槽位(細灰虛線空圈)五種長相各不同, 靜止截圖就分得出; 每種物件的每個狀態(未出場 / 預告中 / 出場提示中 / 生效中 / 縮小預告中; 不亮 / 亮著 / 剛亮起; 閒置 / 按住 / 拖曳 / 彈回)各有獨立外觀
- P1 視覺權重跟著決策迫切度: 全場最亮的是那一張亮著的網(唯一有網格與外光的東西)與氣泡; 7 個不亮槽位降到細灰虛線、不透明度低, 讀得出是槽位但不搶; 換位那一刻給全場最強的動態(掃光 + 角框), 因為那一刻「找網」就是玩家的下一個決策; 勾貼在網的右上緣, 不蓋住網中央的形狀條件
- P2 規則上存在的東西畫面上就存在: 不亮槽位畫成空圈(規則上不收, 但放上去會彈回, 所以要看得到); 預告中的區域與縮小預告都畫出來但長相不同(不生效 / 照舊大小生效); 凍結(冰藍環)、彈回中不可按(半透明)、回命(那一格放大 + 白環)、已鎖定擦過(灰虛線環往內收 = 擦到了但沒變)都有外觀
- P3 一個意義一種長相: 半透明只給「彈回中」, 預告一律用虛線; 灰白 clear 只代表「無色」(透明氣泡、賦形區); 紅只代表危險 / 損失; 白角框只代表「剛出現 / 剛改變」(新區域、區域縮小、網剛亮起共用); 往外擴的環 = 屬性變了, 往內收的灰虛線環 = 沒變; 網條件的形狀符號與氣泡、賦形區共用同一套形狀路徑; 說明頁的網、槽位、氣泡、區域、命、結束畫面直接呼叫遊戲內畫法, 第 3 頁的換位也畫遊戲內同一套掃光與角框
- P4 關鍵區分至少兩條通道: 老闆已明言 prototype 不考慮色弱, 四色只靠色相 + 明度; 語意不同的狀態走兩條通道: 透明 vs 有色(空心 / 實心 + 色相)、亮著 vs 不亮(色 + 網格 + 外光 vs 灰 + 虛線)、預告 vs 生效(虛線 / 實線 + 填色是否填滿)、凍結 vs 走動(環色 + 放大 / 影子)、捕捉(白 + 勾)vs 條件不符彈回(白虛線環、無符號)、回命(白環 + 放大)vs 扣命(紅框 + 空心)、擦過生效(實線環外擴)vs 已鎖定(灰虛線環內收)
- P7 每個元素要掙得版面: 網只要顏色時中央不放任何符號(網本身的顏色就是條件); 不亮槽位不顯示條件、不寫編號; 氣泡上不放數字、也不另加「已鎖定」記號(實心有色本身就是「顏色已沾、不會再變」, 非圓形本身就是「形狀已定」); 網與區域上不寫名稱字樣; 暫停按鈕的「暫停」字樣是規格明文要求。階段切換預告條的「場地即將改變」與物件自己的預告部分重述, 見文末「與理念的張力」
- P13 事件要排隊: 場上只有一條文字(預告條), 且只在預告 2 秒內出現; 捕捉的勾在原槽位、換位掃光從原槽位出發, 兩者是同一條視線上的先後, 不在同一處疊; 出場提示用貼在物件上的角框, 自己淡掉
- P17 進度類資訊, 圖形與數字分工: 氣泡上沒有數字, 依本條邊界「沒有數字、只有圖形時, 圖形照舊畫總進度」, 壽命環畫 12 秒總剩餘比例; 預告的填色、縮小預告的內收虛線與預告條都畫「離生效還多久」
- P18 重要資訊不能只存在一瞬間: 換位提示消失後, 亮著的網本身常駐(外光與網格不淡); 出場提示消失後新區域 / 縮小後的大小常駐; 扣命 / 回命閃光之後, 愛心實心與空心常駐; 分數與存活時間常駐 HUD, 結束畫面再列一次
- P19 資訊貼著物件: 條件畫在網上; 壽命畫在氣泡上; 預告與出場提示畫在那塊區域上; 換位提示畫在新網上並從舊網連過去; 勾畫在那個槽位上
- P21 示意圖選分岔例子: 第 1 頁同一顆氣泡擦過色 A 後、再擦過色 B 仍是色 A(錯誤理解「最後擦的覆蓋」會畫成色 B), 且畫出「擦到了但沒變」的收縮環; 第 2 頁透明放上亮著的網、色 A 放上不亮槽位, 兩格都回到內圈且命仍 4 格, 分開「放錯扣命」「任何槽位都收」兩種誤解; 第 3 頁兩種「之後」位置不同、一種同色一種換色, 都不在原槽位隔壁, 分開「固定換到某處」「每次一定換色」的誤解; 第 4 頁兩顆環同起點, 只有按住的那顆不走

## 物件表

所有函式簽章固定 `(ctx, state)`, 每個函式內部自行 save / restore。state 內沒寫預設值的欄位為必填。「未出場」的區域不呼叫; 不亮的槽位照樣呼叫(畫空槽)。

| 染色區(染 A~D) | `drawPaintZone(ctx, state)` | `x, y`: 中心(用 `Art.layout.zones` 裡該塊); `color`: 0~3; `r`: 目前生效半徑(預設 24; 階段 5 縮小生效後傳 20); `status`: `'preview'`/`'on'`/`'shrink'`(預設 on); `previewT`: 預告進度 0→1(出場預告與縮小預告共用, 2 秒, 1 = 生效那一刻); `shrinkTo`: 縮小後半徑(預設 20); `introT`: 出場提示進度 0→1(生效後 2 秒; 新出場與縮小生效共用; 0、≥ 1 或不傳 = 不畫) | 生效中: 平色池(該色 50% 填色 + 3px 實線色框)+ 中央白框水滴; 沒有高光與壽命環, 跟同色氣泡分得開。預告中: 色虛線框 + 由中心長大的淡色填色(previewT = 1 時剛好填滿)+ 虛線水滴。縮小預告中(`'shrink'`, `r` 仍傳 24): 生效外觀照舊 24(預告期間照舊大小判定)+ 一圈白虛線從 24 往內收, previewT = 1 時停在 20。出場提示中: 生效外觀 + 四個白角框(先縮進再輕脈動, 最後 0.4 秒淡出); 縮小生效後傳 `status:'on', r:20, introT` |

### 繪製層級(由下而上)

1. `drawBackground`
2. `drawInnerRing`
3. `drawPaintZone`、`drawShapeZone`(已出場或預告中的區域; 彼此不重疊, 順序不拘)
4. `drawNet` × 8: **先畫 7 個不亮的, 最後畫亮著的那張**(換位掃光沿軌道穿過其他槽位, 要蓋在它們上面)
5. 閒置、被按住與彈回中的 `drawBubble`
6. 拖曳中的 `drawBubble`(永遠最上層的遊戲物件; 拖過區域或網時蓋住它們, 屬正常)
7. `drawHud`、`drawPauseButton`、`drawStageNotice`(預告期間)
8. `drawPauseMenu`(暫停時)
9. 標題 / 輸入裝置 / 說明 / 結束畫面各自整面重畫, 不需先畫遊戲畫面; 從暫停開說明時直接只畫 `drawGuidePage`

### 狀態對照(給 RD 的接法)

| 規格狀態 | 區域(`drawPaintZone` / `drawShapeZone`) |

|---|---|

### 與理念的張力(交製作人決定)

- 階段切換預告條(`drawStageNotice`)的「場地即將改變」與各區域自己的預告外觀部分重述(P7)。保留理由: 區域都在內圈裡、預告外觀較小(半徑 24), 拖曳中視線不一定看得到。若試玩覺得多餘, 不呼叫即可
- 換位提示的掃光是本版唯一的大動態(P8 候選「動得越多, 每個動作分到的注意力越少」), 每次捕捉都會播。刻意把它做強是回應規格待定第 1 條「找網」; 若試玩指標 1 的槽位差 4 格與 2 格差距已小於 0.4 秒、老闆又覺得畫面太吵, 可把 `from` 拿掉(只留角框), 其他不受影響
- 「已鎖定」擦過的收縮灰環: 沾色後半路擦過別塊會頻繁出現(規格估計約七成出圈方向會路過別塊)。它在教「沾過就不再變」, 所以保留; 若試玩覺得吵, `swipeKind:'locked'` 改成不觸發即可
