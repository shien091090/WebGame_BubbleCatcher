# 音效說明(對應 spec v18「音效清單」, decisions v26 選曲)

## 聲音風格

回饋音沿用上一版的明亮晶片音與玻璃叮聲(Kenney CC0), 一個都沒換。背景音樂換成老闆選定的三首電子曲, 三首都是每拍都有大鼓的四拍電子樂: 第 1 關 Voice Over Under(明亮彈跳的合成器電子, 由 135 放慢到 105 BPM)、第 2 關 Cluster Block(8-bit / 16-bit 合成器的迪斯可電子, 由 133 放慢到 115 BPM)、第 3 關 Metallic Mistress(16-bit 風格重吉他加工業舞曲, 原速 125 BPM)。換關提示仍用鋼鼓上行樂句。

## 事件表

一次性音效都用 `Sound.play(name, opts)`, `opts` 可省略。共用欄位 `opts.x`(0~1280, 動作發生處的 x 座標, 可省略): 有給就依左右位置做輕微立體聲定位。

與上一版的差異(RD 要改的地方):
- **三首背景音樂全換, 拍速改為 105 / 115 / 125 BPM**(上一版 100 / 115 / 128)。事件名、`playMusic` 等呼叫方式不變
- **拍速、小節數、曲長、第一拍位置、第 3 首循環起訖一律從 `Sound.getMusicInfo(name)` 讀**, 不要寫死數字(spec「曲子設定」: 程式不得寫死拍速)。本版 `getMusicInfo` 多回傳 5 個欄位(見「介面」), 原有欄位不變
- 一次性音效的事件名、opts、素材、音量全部不變

素材格式: 短音效以 16-bit PCM base64 內嵌在 sound.js, `init()` 時直接填進 AudioBuffer, 用 Web Audio 播放。背景音樂的 mp3 也以 base64 內嵌在 sound.js(sound.js 因此約 5.9 MB), 頁面載入時就用離線 context 解碼, 不經 fetch, file:// 可用。沒有 Web Audio 時退回 `audio/assets/*.mp3` 的 HTMLAudio(短音效 4 複本播放池; 音樂改用單一元素, 第 3 首的循環接縫不保證無縫)。

### 量法與結果

**時間伸縮**: Rubber Band 4.0.0 命令列工具的 R3(fine)引擎, 離線處理整首、立體聲中央聚焦選項, 只改時間不改音高。同時用 R2 引擎(打擊清晰模式)做了一份對照, 以下面的大鼓清楚度比: 第 1 首兩者都 36/36 小節清楚, 第 2 首 R3 37/40 優於 R2 36/40、清楚度中位 35.8 對 32.1 dB, 故兩首都用 R3。沒有 ffmpeg, 所以沒有比 atempo。

**BPM**: 頻譜通量起音曲線(每 2.9 毫秒一點), 在目標 ±0.05 BPM 內以 0.0005 步距加相位搜尋, 找拍點起音總和最大的拍速; 再以每 8 小節一窗量拍點相位做線性回歸看漂移。量的是**最後的 mp3 截取段本身**:

| | 擬合 BPM | 漂移 | 8 小節窗殘差最大 | 拍格對實際起音(中位) |
|---|---|---|---|---|
| 第 1 首 | 104.9995 | +0.16 毫秒/分 | 0.23 毫秒 | +0.23 毫秒 |
| 第 2 首 | 115.0000 | 0.00 毫秒/分 | 1.25 毫秒 | −0.84 毫秒 |
| 第 3 首 | 125.0010 | −0.11 毫秒/分 | 0.40 毫秒 | +0.07 毫秒 |

一整首累積誤差都在 1 毫秒以內, 定為 105.00 / 115.00 / 125.00。「拍格對實際起音」= 以 0.05 秒 + k × 每拍秒數為拍格, 每拍實際起音(1 毫秒能量最陡上升處)與拍格的差, 取中位。

**大鼓清楚度**(經驗文件的量法): 35~110 Hz 帶通、5 毫秒包絡; 每拍量拍點前後的起音上升量, 減去同拍反拍與兩個十六分位置的最大上升量 = 清楚度。一拍「清楚」= 上升 ≥ 10 dB 且清楚度 ≥ 3 dB; 一小節四拍都清楚才算清楚小節。拍格直接用遊戲時鐘會用的拍格(0.05 秒 + k × 每拍秒數), 只量關內小節。放慢前後對照用原曲同一段(同樣的小節):

| | 四拍都清楚的小節 | 不清楚的關內小節 | 每拍起音中位 / 最小 | 清楚度中位 | 清楚度 ≥ 3 dB 的拍 | ≥ 10 dB 的拍 |
|---|---|---|---|---|---|---|
| 第 1 首 原曲 135 | 36/36(100%) | 無 | 58.2 / 43.7 dB | 34.6 dB | 100% | 99.3% |
| 第 1 首 放慢 105(本版) | **36/36(100%)** | 無 | 55.2 / 41.8 dB | 31.9 dB | 100% | 100% |
| 第 2 首 原曲 133 | 38/40(95%) | 第 14、15 小節 | 46.3 / 18.0 dB | 32.7 dB | 98.1% | 94.4% |
| 第 2 首 放慢 115(本版) | **37/40(92.5%)** | 第 12、13、14 小節 | 47.1 / 15.0 dB | 35.8 dB | 96.2% | 94.4% |
| 第 3 首 原速 125(本版) | **48/48(100%)** | 無 | 43.6 / 30.7 dB | 22.8 dB | 100% | 90.6% |

- 第 1 首放慢後沒有變糊: 四拍都清楚的小節仍是 100%(遠高於 85% 的回報門檻), 清楚度中位只降 2.7 dB。整首逐小節掃描, 放慢後全曲 110 小節只多出 1 小節不清楚(原曲第 71 小節, 不在截取段內)
- 第 2 首關內第 12~14 小節(第 2 關前段中間, 約關內 23~29 秒): 每拍大鼓都在(起音 ≥ 15 dB), 但第 12、13 小節第 1、3 拍附近的貝斯在反拍一樣響, 清楚度在 −1.7~2.7 dB 之間, 是門檻邊緣; 第 14 小節第 2、4 拍大鼓變輕(起音 15 dB)。原曲這段本來就偏弱(原曲第 14、15 小節不過), 放慢讓第 12、13 小節從勉強過變成勉強不過。整首沒有更好的 41 小節窗(其餘位置都會碰到原曲第 49~52 或 69~76 小節附近的弱鼓段), 所以從曲首截
- 第 3 首清楚度中位比另外兩首低, 是因為重吉他與貝斯在拍間持續有低頻; 但 48 小節每一拍都過門檻, 最小起音 30.7 dB
- 三首的預備拍那一小節每一拍都有大鼓(起音 33~73 dB)

**截取**: 第 1、2 首從原曲開頭截(曲首第一拍就是大鼓, 預備拍那一小節 = 原曲第 1 小節)。第 3 首選原曲第 4~52 小節: 原曲第 1~4 小節是前奏, 以 8 小節為一個樂句(第 5、13、21… 小節是樂句頭), 第 53~60 小節是 8 小節無鼓的 breakdown; 截取讓循環段(原曲第 5~52 小節)正好是 6 個完整樂句、循環終點落在 breakdown 之前, 預備拍那一小節是前奏最後一小節。

**第 3 首循環**: 循環段 = 關內第 1~48 小節(92.16 秒)。接縫處最後 30 毫秒交叉淡入原曲第 5 小節之前的聲音, 循環終點後多放 0.5 秒原曲第 5 小節開頭的聲音當保險。量測: 把循環段頭尾相接, 接縫前 8 小節到後 8 小節(每 4 小節一窗)的拍格偏差在 −3.0~−2.5 毫秒之間, 不斷拍、不偏移; 接縫處跨拍的大鼓起音照常(接縫後第 1 拍 39.2 dB)。接縫那一下的頻譜跳動與原曲自己從前奏(第 4 小節)進入第 5 小節那一下一樣大(0.128 對 0.128), 聽起來是「樂句結尾 → 下一個樂句開頭」, 不是剪接。

**共同處理**: 開頭 2 毫秒淡入、前面加 0.05 秒數位靜音(解碼校正用)、響度統一到 −19 dBFS RMS(增益 +0.73 / +0.69 / +1.21 dB)、第 1、3 首超過 0.95 的少數峰值用 2 毫秒前瞻峰值限制壓住(影響約 0.23 秒 / 0.06 秒的樣本)、44.1 kHz 立體聲 128 kbps mp3(Python soundfile / libsndfile 寫出, 本機解碼後開頭偏移 0~2 樣本)。

### 對齊規則

- 時鐘拍 `beat` = 該關的時鐘拍序號(預備拍為 −4 ~ −1, 關內第 0 拍 = 0, 可為小數)。每首歌的第 0 秒(= 音檔的 `firstBeatInFileSec`)= 該關第 −4 拍
- 歌曲位置 = (beat + 4) × 該首每拍秒數。第 1、2 首超過曲長(關末之後)就不出聲。第 3 首: beat ≥ 192(48 小節走完)之後, 位置 = 1 小節 + (beat 取 192 的餘數) × 每拍秒數, 也就是回到關內第 1 小節; 拍序號照樣往下累計, 傳進來的值不用歸零
- 音樂預設做輸出延遲補償: 對齊時把音樂往前推 `getOutputLatency()` 秒, 讓玩家**聽到**的拍子對齊時鐘拍點
- 解碼器開頭填充自動校正: 解碼後比對檔內第一個聲音的位置, 差異在 0.1 秒內就自動修正

### 介面

| 介面 | 用途 | 何時呼叫 |
|---|---|---|
| `Sound.playMusic('stage1' 或 'stage2' 或 'stage3')` | 從歌曲開頭(= 該關第 −4 拍)開始播; 若前一首還在響, 前一首 0.3 秒淡出 | 開局(含重開、再玩一次)預備拍第 −4 拍那一刻播 `stage1`; 換關那一刻(新關第 −4 拍)播下一首 |
| `Sound.playMusic(name, { beat })` | 讓音樂「此刻」對到該關時鐘拍 `beat` 開始播 | 呼叫時時鐘已走過 −4 拍一點點時, 傳當下的時鐘拍較準 |
| `Sound.syncMusic(beat, toleranceSec?)` | 傳入當下時鐘拍; 音樂偏離超過容許值(預設 0.04 秒)就對回時鐘。回傳偏差秒數(音樂 − 時鐘, 正值 = 音樂超前); 第 1、2 首播完後回 0 | 局中(含預備拍)每幀或每拍呼叫; 偏差在容許內什麼都不做 |
| `Sound.pauseMusic()` | 停下音樂(時鐘由 RD 凍結) | 暫停那一刻 |
| `Sound.resumeMusic(beat)` | 從時鐘拍 `beat` 對應的位置接著播 | 恢復那一刻, 傳恢復時的時鐘拍(= 暫停時的時鐘拍) |
| `Sound.seekMusic(beat)` | 同 `resumeMusic`, 強制立刻對到 `beat` | 需要手動對齊時 |
| `Sound.stopMusic()` | 0.15 秒淡出並停止 | 局結束、離開遊戲畫面(結束畫面、回標題)時 |
| `Sound.getMusicInfo(name)` | 回傳曲子設定物件(欄位見下); 未知名稱回 null | **建拍子時鐘、算關長、算換關時刻都用它**; 頁面載入後即可呼叫, 不需要 init |
| `Sound.isMusicReady(name)` | 該首是否已解碼好 | 除錯用; 不需要等它: 解碼完成前呼叫 `playMusic`, 解完會自動從「當下應該在的位置」開始播 |
| `Sound.getOutputLatency()` | 音訊輸出延遲(秒) = outputLatency + baseLatency; init 前回 0 | 判定偏移補償與埋點參考 |
| `Sound.getMusicBeat()` | 目前「聽到的」音樂對應的時鐘拍; 沒在播回 null | 埋點或除錯 |
| `Sound.setMusicLatencyCompensation(bool)` | 開關音樂的輸出延遲補償(預設開) | 通常不用動; 若 RD 決定在判定端補延遲, 關掉以免補兩次 |
| `Sound.SONG_START_BEAT` | −4 | 常數 |

`getMusicInfo(name)` 回傳的欄位(**本版新增**的標粗):

| 欄位 | 意義 | stage1 / stage2 / stage3 |
|---|---|---|
| **`file`** | 曲檔路徑(相對 index.html) | `audio/assets/music_stage1.mp3` 等 |
| `bpm` | 實測 BPM, 時鐘用它 | 105 / 115 / 125 |
| `beatSec` | 每拍秒數 = 60 ÷ bpm | 0.5714… / 0.5217… / 0.48 |
| `bars` | 檔內小節數(含預備拍) | 37 / 41 / 49 |
| `levelBars` | 關長小節數(第 3 首為一輪) | 36 / 40 / 48 |
| `songStartBeat` | 歌曲第 0 秒對應的時鐘拍 | −4 |
| `lengthSec` | 歌曲長度(不含檔頭靜音) | 84.571429 / 85.565215 / 94.08 |
| **`firstBeatInFileSec`** | 第一拍(預備拍第 −4 拍)在音檔中的秒數 | 0.05 / 0.05 / 0.05 |
| **`levelStartInFileSec`** | 關內第 0 拍在音檔中的秒數 | 2.3357 / 2.1370 / 1.97 |
| `loop` | 是否循環 | false / false / true |
| `loopStartBeat` / `loopBeats` | 循環起點的時鐘拍 / 一輪拍數 | null / null / 0 與 192 |
| **`loopStartInFileSec`** / **`loopEndInFileSec`** | 循環起訖在音檔中的秒數 | null / null / 1.97 與 94.13 |

`...InFileSec` 是音檔本身的秒數(未經解碼器校正), 只供核對或退路使用; 用 `playMusic` / `syncMusic` 播放時 sound.js 已自動處理, RD 不必自己換算。

**權威**: 時鐘以關內時間為準, 音樂永遠跟著時鐘走; sound.js 不提供時鐘, 也不會反過來改時鐘。

**換關那一刻建議呼叫順序**: `play('stageChange')` → `playMusic('stage2')`(或 `stage3`)→ `play('countIn', { left: 4 })`。第 1、2 首的音檔長度剛好到關末, 換關時上一首已自然結束。

**靜音**: `setMuted(true)` 只把總音量降到 0, 音樂照樣在背景走(對齊不會跑掉), 取消靜音時立刻是對的位置。靜音狀態的本機紀錄由 RD 做(載入時呼叫 `setMuted(記錄值)`, init 前呼叫也有效)。

**其他**:
- `init()` 之前的 `play`、`playMusic` 一律靜默丟棄; 開局按「開始」那一下若同時是 init, 先 `init()` 再 `playMusic`
- 剛 init 的 AudioContext 可能晚幾十毫秒才真正出聲, 第一個 `syncMusic` 會把差距對回來

## 同時觸發的處理

| 同一刻可能一起發生 | 處理 |
|---|---|
| 觸發 + 光門換位(必定同幀) | `netSwap` 若在 `catch` 之後 50 毫秒內呼叫, 自動延後 70 毫秒才響, 兩聲分開; 光門換位音量最低 |
| 同一刻兩次換位(第 2 關跳位那一刻換位當下即判觸發, 接著輪替; 或自動換位與觸發同幀) | 兩次都照呼叫 `netSwap` 也可: 40 毫秒內的第二次自動略過, 只響一次 |
| 觸發 + 送進光門踩拍(`onBeat`) | 都響; 踩拍(0.85~1.0)明顯壓過觸發(0.45) |
| 觸發 + 送進光門踩拍(第 2 或 3 級)+ 整串(`beatChain`) | 都照呼叫: 踩拍那一下先出, 整串的上揚掃頻同時起、再往上跑兩個高音(0.1、0.2 秒), 聽起來是「第 N 級叮 + 一串往上衝」, 跟單獨第 3 級分得開 |
| 地板輪轉 + 染上踩拍(輪轉那一拍剛好染上)或 + 自動換位 | 都響; 輪轉是短機械「喀嚓」(兩下, 相隔 0.11 秒), 沒有音高, 跟玻璃叮聲與換位的上揚掃頻分得開 |
| 地板輪轉 + 背景音樂 | 輪轉落在第 3 首每 2 小節的第 1 拍, 喀嚓聲疊在大鼓上, 當成一下額外的打擊 |
| 沾錯消失 + 血量危險(沾錯讓血量跌破 40) | 都響; 危險樂句較大聲較長, 沾錯是 0.16 秒的短促低音錯誤聲 |
| 沾錯消失 + 過期(同幀) | 都響; 沾錯(0.4, 0.16 秒)明顯比過期(0.5, 0.42 秒下滑音)輕、短 |
| 換關 + 預備拍第 −4 拍 + 新歌開頭(必定同一刻) | 都響; 換關鋼鼓樂句 1.4 秒會蓋過前 2~3 個預備拍叮聲的時段, 但音色與音高不同, 預備拍叮聲仍聽得出; 換關音量刻意比預備拍低(0.6 對 0.8) |
| 過期 + 血量危險 | 都響; 危險音量較大, 過期只是短下滑音 |
| 同幀多顆過期 | 每顆各呼叫一次也可, 會疊成較厚的一聲 |
| 血量危險 | 一秒內重複呼叫只響第一次(保險; 規則上本來只響一次) |
| 預備拍 + 背景音樂 | 預備拍叮聲疊在歌曲第一小節的拍上, 同步; 三首的預備拍那一小節都有每拍大鼓 |

響度由大到小: 整串 > 踩拍第 3 級 > 第 2 級 > 第 1 級 > 預備拍 ≈ 地板輪轉 > 危險 > 換關 > 過期 > 觸發 > 光門換位 > 沾錯消失; 背景音樂三首統一到 −19 dBFS RMS(與上一版相同), 再乘音樂匯流排 0.7, 所以回饋音與音樂的相對大小跟上一版一樣。

## 理念或經驗落實

- 程式合成的短循環被嫌膩(品味, 本作 round-7): 三首都是現成整首曲子截段; 第 3 首一輪 48 小節(92 秒)才循環一次, 沒有疊合成層。
- 精準 BPM 曲子去哪找(素材來源): 本版曲目由老闆選定, 不再選曲; 仍照同一套方法實測截取段的拍速與漂移, 三首漂移都在 ±0.2 毫秒/分以內。
- 背景音樂節奏感太弱、量大鼓清楚度(辨識, 本作 round-8): 放慢後重量 35~110 Hz 大鼓清楚度並逐小節掃描, 截取窗避開無鼓的過門與 breakdown(第 3 首的循環終點刻意放在 breakdown 之前); 放慢前後對照見上節。
- 量清楚度時相位要用低頻找(辨識, 本作選曲調查): 選窗時相位用低頻清楚度搜尋; 最後的驗收則直接用遊戲時鐘的拍格(0.05 秒 + k × 每拍)量, 量到的就是玩家實際聽到的對齊情形。
- 低拍速又要每拍大鼓的曲子難找(辨識, 本作選曲調查): 本版是另一條路——拿每拍大鼓的快曲用保留音高的時間伸縮放慢到 105 / 115; 量得第 1 首大鼓清楚度幾乎不受影響, 第 2 首多 1 小節落到門檻邊緣。
- 背景音樂對齊與無縫循環(技術): 沿用內嵌 mp3 + 離線解碼 + 開頭填充自動校正 + 循環終點後的保險段; 第 3 首用同一套截取與接縫流程。
- CC BY 音樂的署名(授權): 三首都要署名(1 首 CC BY 4.0、2 首 CC BY 3.0), 且前兩首要註明已調速; 署名文字在 credits.md, 遊戲畫面上的署名要整段換掉。
- 即時回饋音延遲(技術, SlimeTetris round-11): 回饋音沿用上一版, 都已量過出聲時間並以 PCM 內嵌, 本版未動。
