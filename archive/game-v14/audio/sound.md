# 音效說明(對應 spec v14「音效清單」)

## 聲音風格

回饋音沿用上一版的明亮晶片音與玻璃叮聲(Kenney); 背景音樂換成三首現成曲, 一關一種曲風: 第 1 關明亮放鬆的合成器流行、第 2 關迪斯可、第 3 關暗色工業電子。換關提示用鋼鼓上行樂句, 跟晶片音的清場分得開。

## 事件表

一次性音效都用 `Sound.play(name, opts)`, `opts` 可省略。共用欄位 `opts.x`(0~1280, 動作發生處的 x 座標, 可省略): 有給就依左右位置做輕微立體聲定位。

| 事件名 | 對應 spec 音效清單 | 何時呼叫 | opts 欄位 | 素材 | 相對音量 | 循環 |
|---|---|---|---|---|---|---|
| `countIn` | 預備拍 | 開局與每次換關, 預備拍第 −4、−3、−2、−1 拍各一次(拍點那一刻, 用該關拍速) | `left`: 還剩幾拍開始, 依序傳 4、3、2、1; 音高 do→re→mi→so 逐拍升高, `left: 1` 最高也最響 | count_in_pluck | 0.8 | 否 |
| `stageChange` | 換關 | 第 1、2 關關末(歌曲結束、場上清空)那一刻, 一次 | 無 | stage_change_steel(**本版新增**) | 0.6 | 否 |
| `onBeat` | 踩拍 | 計次節點踩拍那一刻: 第一次沾上、第二次沾上、送進網(動作那一刻)。沒踩拍不呼叫; 抓起不再是節點, 不呼叫 | `step`: 這一下的踩拍級數 1 / 2 / 3(spec 的漸強級數, 省略當 1); 級數越高音越高、疊的層越多。`x` | on_beat_glass(第 1 級單音; 第 2 級高三度主音 + 原音; 第 3 級高五度主音 + 原音 + 高八度) | 第 1 級 0.85、第 2 級 0.94、第 3 級 1.0(主音) | 否 |
| `beatChain` | 整串踩拍 | 整串踩拍成立的捕捉那一刻(與送進網那一下的 `onBeat` 同一刻, 兩個都要呼叫) | `x` | beat_chain_powerup, 再接兩個更高的 on_beat_glass(延後 0.1、0.2 秒, 往上跑) | 0.9 + 疊層 | 否 |
| `catch` | 捕捉 | 捕捉成功那一刻(不論有沒有踩拍) | `x` | catch_confirm | 0.45 | 否 |
| `netSwap` | 網換位 | 新網亮起那一刻: 捕捉後輪替(與捕捉同一幀), 以及每關第 0 拍第一張網亮起時 | `x`: 新網的 x | net_swap_phaser_up | 0.4 | 否 |
| `expire` | 過期 | 氣泡壽命歸零消失那一刻; 同幀多顆可每顆各呼叫一次 | `x` | expire_phaser_down | 0.5 | 否 |
| `clear` | 清場 | 清場成立那一刻 | 無 | clear_jingle | 0.75 | 否 |
| `danger` | 血量危險 | 血量降到 ≤ 40 進入危險狀態那一刻, 一次(解除前不再呼叫) | 無 | danger_jingle | 0.65 | 否 |
| 背景音樂 `stage1` / `stage2` / `stage3` | 背景音樂 第 1 / 2 / 3 首 | 見下節 | 見下節 | music_stage1 / 2 / 3 | 音樂匯流排 0.7(三首響度已統一) | 第 1、2 首否; 第 3 首是 |

不出聲(不要呼叫): 卡死縮短、沒踩拍的節點、段切換(預告與出場提示)、沾地板回饋與已鎖定回饋、條件不符彈回、放在其他位置彈回、抓起。

與上一版的差異(RD 要改的地方):
- 新增事件 `stageChange`
- `onBeat` 的 `step` 改成「踩拍級數 1~3」(上一版是節點序 1~4); 欄位名不變。上一版抓起也呼叫 `onBeat`, 這版抓起不呼叫
- 背景音樂名稱從 `main` 改成 `stage1` / `stage2` / `stage3`; 常數 `Sound.BPM` / `BEAT_SEC` / `LOOP_BEATS` 拿掉, 改用 `Sound.getMusicInfo(name)`(各首拍速不同)
- `beatChain` 不再吞掉同一刻的 `onBeat`; 兩個都照呼叫

素材格式: 短音效以 16-bit PCM base64 內嵌在 sound.js, `init()` 時直接填進 AudioBuffer, 用 Web Audio 播放。背景音樂的 mp3 也以 base64 內嵌在 sound.js(sound.js 因此約 6 MB), 頁面載入時就用離線 context 解碼, 不經 fetch, file:// 可用。沒有 Web Audio 時退回 `audio/assets/*.mp3` 的 HTMLAudio(短音效 4 複本播放池; 音樂改用單一元素, 第 3 首的循環接縫不保證無縫)。

spec 數值參數表的檢核: 第 1 關 100.00(要求 99~105)、第 2 關 115.00(目標 115 ±5)、第 3 關 130.00(目標 130 ±5); 相鄰兩關差 15 / 15(要求 ≥ 10)。三首都正好等於規格目標拍速, 關長秒數、半拍間隔、判定窗毫秒值不必重算。

BPM 怎麼量的: 原曲作者的曲庫資料標示 100 / 115 / 130; 再對實際截取的那一段量: 以頻譜通量做起音曲線(每 2.9 毫秒一點), 在目標 ±0.05 BPM 內以 0.0005 的步距、配合相位搜尋, 找讓拍點起音總和最大的拍速, 得 99.9995 / 115.000 / 129.9975; 再以每 8 小節為一窗量拍點相位, 做線性回歸看漂移: 第 1 首 0、第 2 首 0.18 毫秒/分鐘、第 3 首 −1.6 毫秒/分鐘(校正後 130.001), 各窗殘差最大 0 / 0.35 / 3.2 毫秒。換算一整首的累積誤差都在 3 毫秒以內, 拍速穩定。另抽查每一拍實際起音時刻(1 毫秒能量最陡上升處)與拍格的差, 中位數 3.0 / −2.8 / 0.0 毫秒。

截取怎麼定: 截取起點落在原曲段落的開頭前一小節, 讓「預備拍那一小節 = 前奏最後一小節」, 關內第 1 小節正好是鼓組全開的段落開頭(第 1、3 首在這一刻音量各跳升約 6 / 24 dB; 第 2 首前奏 1 小節沒有鼓, 第 1 小節起鼓進來)。

第 3 首循環怎麼做: 循環段 = 關內第 1~48 小節, 長度正好 48 小節。接縫處最後 30 毫秒交叉淡入原曲第 5 小節之前的聲音, 並在循環終點後多放 0.5 秒原曲第 5 小節開頭的聲音當保險(解碼位置有幾毫秒誤差也不會跳)。量測: 把循環段頭尾相接後, 接縫前後各 8 小節的拍格偏差在 1.5~3.5 毫秒之間, 沒有斷拍或偏移; 接縫那一下的頻譜跳動低於一般拍點起音的第 95 百分位。原曲第 53 小節(接縫後本來接的那段)與第 5 小節的頻譜相似度 0.961, 與同段落內相隔 8 小節的相似度 0.967 相當, 接回去是同一種段落的聲音。

曲中要注意的地方(待試玩):
- 第 3 首關內第 17~20 小節(原曲第 21~24 小節)是 4 小節的間奏, 大鼓很弱, 拍子主要靠其他聲部; 剛好落在第 3 關後段開頭。循環時每輪都會出現一次
- 第 2 首的預備拍那一小節是前奏的上揚音效, 沒有鼓, 預備拍主要靠 `countIn` 叮聲

### 對齊規則

- 時鐘拍 `beat` = 該關的時鐘拍序號(預備拍為 −4 ~ −1, 關內第 0 拍 = 0, 可為小數)。每首歌的第 0 秒 = 該關第 −4 拍
- 歌曲位置 = (beat + 4) × 該首每拍秒數。第 1、2 首超過曲長(關末之後)就不出聲。第 3 首: beat ≥ 192(48 小節走完)之後, 位置 = 1 小節 + (beat 取 192 的餘數) × 每拍秒數, 也就是回到關內第 1 小節; 拍序號照樣往下累計, 傳進來的值不用歸零
- 音樂預設做輸出延遲補償: 對齊時把音樂往前推 `getOutputLatency()` 秒, 讓玩家**聽到**的拍子對齊時鐘拍點
- 解碼器開頭填充自動校正: 解碼後比對檔內第一個聲音的位置, 差異在 0.1 秒內就自動修正(本機量: 編碼前後差 0~0.34 毫秒)

### 介面

| 介面 | 用途 | 何時呼叫 |
|---|---|---|
| `Sound.playMusic('stage1' 或 'stage2' 或 'stage3')` | 從歌曲開頭(= 該關第 −4 拍)開始播; 若前一首還在響, 前一首 0.3 秒淡出 | 開局(含重開、再玩一次)預備拍第 −4 拍那一刻播 `stage1`; 換關那一刻(新關第 −4 拍)播下一首 |
| `Sound.playMusic(name, { beat })` | 讓音樂「此刻」對到該關時鐘拍 `beat` 開始播 | 呼叫時時鐘已走過 −4 拍一點點時, 傳當下的時鐘拍較準 |
| `Sound.syncMusic(beat, toleranceSec?)` | 傳入當下時鐘拍; 音樂偏離超過容許值(預設 0.04 秒)就對回時鐘。回傳偏差秒數(音樂 − 時鐘, 正值 = 音樂超前); 第 1、2 首播完後回 0 | 局中(含預備拍)每幀或每拍呼叫; 偏差在容許內什麼都不做 |
| `Sound.pauseMusic()` | 停下音樂(時鐘由 RD 凍結) | 暫停那一刻 |
| `Sound.resumeMusic(beat)` | 從時鐘拍 `beat` 對應的位置接著播 | 恢復那一刻, 傳恢復時的時鐘拍(= 暫停時的時鐘拍) |
| `Sound.seekMusic(beat)` | 同 `resumeMusic`, 強制立刻對到 `beat` | 需要手動對齊時 |
| `Sound.stopMusic()` | 0.15 秒淡出並停止 | 局結束、離開遊戲畫面(結束畫面、回標題)時 |
| `Sound.getMusicInfo(name)` | 回傳 `{ bpm, beatSec, bars, levelBars, songStartBeat: -4, lengthSec, loop, loopStartBeat, loopBeats }`; 未知名稱回 null | 需要用歌曲的實際 BPM 建時鐘時(三首 = 100 / 115 / 130) |
| `Sound.isMusicReady(name)` | 該首是否已解碼好 | 除錯用; 不需要等它: 解碼完成前呼叫 `playMusic`, 解完會自動從「當下應該在的位置」開始播 |
| `Sound.getOutputLatency()` | 音訊輸出延遲(秒) = outputLatency + baseLatency; init 前回 0 | 判定偏移補償與埋點參考 |
| `Sound.getMusicBeat()` | 目前「聽到的」音樂對應的時鐘拍; 沒在播回 null | 埋點或除錯 |
| `Sound.setMusicLatencyCompensation(bool)` | 開關音樂的輸出延遲補償(預設開) | 通常不用動; 若 RD 決定在判定端補延遲, 關掉以免補兩次 |
| `Sound.SONG_START_BEAT` | −4 | 常數 |

**權威**: 時鐘以關內時間為準, 音樂永遠跟著時鐘走; sound.js 不提供時鐘, 也不會反過來改時鐘。

**換關那一刻建議呼叫順序**: `play('stageChange')` → `playMusic('stage2')`(或 `stage3`)→ `play('countIn', { left: 4 })`。第 1、2 首的音檔長度剛好到關末, 換關時上一首已自然結束。

**靜音**: `setMuted(true)` 只把總音量降到 0, 音樂照樣在背景走(對齊不會跑掉), 取消靜音時立刻是對的位置。靜音狀態的本機紀錄由 RD 做(載入時呼叫 `setMuted(記錄值)`, init 前呼叫也有效)。

**其他**:
- `init()` 之前的 `play`、`playMusic` 一律靜默丟棄; 開局按「開始」那一下若同時是 init, 先 `init()` 再 `playMusic`
- 剛 init 的 AudioContext 可能晚幾十毫秒才真正出聲, 第一個 `syncMusic` 會把差距對回來

## 同時觸發的處理

| 同一刻可能一起發生 | 處理 |
|---|---|
| 捕捉 + 網換位(必定同幀) | `netSwap` 若在 `catch` 之後 50 毫秒內呼叫, 自動延後 70 毫秒才響, 兩聲分開; 網換位音量最低 |
| 捕捉 + 送進網踩拍(`onBeat`) | 都響; 踩拍(0.85~1.0)明顯壓過捕捉(0.45) |
| 捕捉 + 送進網踩拍(第 2 或 3 級)+ 整串(`beatChain`) | 都照呼叫: 踩拍那一下先出, 整串的上揚掃頻同時起、再往上跑兩個高音(0.1、0.2 秒), 聽起來是「第 N 級叮 + 一串往上衝」, 跟單獨第 3 級分得開 |
| 捕捉 + 清場(最後一顆在空檔中被收) | 都響; 清場是 0.8 秒樂句, 捕捉音短且小 |
| 換關 + 預備拍第 −4 拍 + 新歌開頭(必定同一刻) | 都響; 換關鋼鼓樂句 1.4 秒會蓋過前 2~3 個預備拍叮聲的時段, 但音色與音高不同, 預備拍叮聲仍聽得出; 換關音量刻意比預備拍低(0.6 對 0.8) |
| 換關 + 清場(關末那一幀清場) | 都響; 清場是晶片音、換關是鋼鼓, 音色分得開 |
| 過期 + 清場(靠過期清場) | 都響 |
| 過期 + 血量危險 | 都響; 危險音量較大, 過期只是短下滑音 |
| 同幀多顆過期 | 每顆各呼叫一次也可, 會疊成較厚的一聲 |
| 血量危險 | 一秒內重複呼叫只響第一次(保險; 規則上本來只響一次) |
| 預備拍 + 背景音樂 | 預備拍叮聲疊在歌曲第一小節(前奏最後一小節)的拍上, 同步 |

響度由大到小: 整串 > 踩拍第 3 級 > 第 2 級 > 第 1 級 > 預備拍 > 清場 > 危險 > 換關 > 過期 > 捕捉 > 網換位; 背景音樂三首統一到 −19 dBFS RMS, 再乘音樂匯流排 0.7。

## 理念或經驗落實

- 即時回饋音聽起來延遲(技術, SlimeTetris round-11): 沿用的素材都已量過「出到峰值一成的時間」並在 0.03 秒內; 新增的換關鋼鼓量得 0.020 秒。全部短音效以 16-bit PCM base64 內嵌、init 時同步填進 AudioBuffer、用 Web Audio 播放, 沒有 Web Audio 才退回播放池。背景音樂也改成內嵌 + 載入時先解碼, 第一下「開始」就能準時起拍。
- 程式合成的短循環被嫌膩(品味, 本作 round-7): 三首都換成現成整首曲子截段, 第 1、2 首整關不重複, 第 3 首一輪 48 小節(約 89 秒)才循環一次。
- 精準 BPM 曲子去哪找(素材來源): 用 incompetech 曲庫的 BPM 清單篩候選, 再實測截取段的拍速與漂移。
- 背景音樂對齊與無縫循環(技術): 內嵌 mp3 + 離線解碼 + 開頭填充自動校正 + 循環終點後的保險段, 做法見上節。
