# 捕泡手 美術規格(style.md)

RD 只需讀本檔。`art.js` 掛在 `window.Art`, 非 ES module。art.js 內含中文字串, `index.html` 必須有 `<meta charset="utf-8">`, 否則 file:// 下所有文字變亂碼。

本版(v12 規格 + v13 就地修正: 波次生成、命上限 5、清場回饋)相對 game-v10 的變動:
- **`drawBubble` 外觀重做**(第 5 輪老闆回饋「染色地板、賦形地板、氣泡三者長太像」, 只改氣泡、地板維持): 氣泡改成立在地上的立體球(左上亮右下暗的漸層 + 主高光 + 小亮點 + 右下反光弧 + 常駐落影); 地板仍是平塗、無影。函式名與既有 state 不變
- `drawBubble` **新增 `spawnT`**(冒出演出, 0→1, 建議 0.4 秒): 地面一圈扁橢圓水紋 + 本體從地面彈起(拉長 → 回彈), 壽命環淡入。波次一批 N 顆依序冒出時, 每顆各自從冒出那一刻起跑 `spawnT`
- `drawBubble` **新增 `hover`**(滑鼠停在可按的閒置氣泡上): 稍微浮起(落影變大、放大 1.04)+ 本體變亮。只在 `mode:'idle'` 時有效
- **新增 `drawClearFx(ctx, state)`**: 清場回饋, 需要 RD 接(見物件表與繪製層級)
- `drawHud`: `hpMax` 預設改 5(命上限 5), 5 格愛心排得下, 版位不變
- `drawEndScreen`: 本來就只顯示存活時間與分數, 不變(不顯示清場次數)
- `drawGuidePage`: state 不變; 第 2 頁三格滿命 5 格、第 5 頁命 4 → 5 / 5 → 4、第 6 頁命 5 → 0 且結束畫面只示意存活時間; 圖裡的氣泡自動換成新外觀
- 其他函式(`drawBackground`、`drawInnerRing`、`drawPaintZone`、`drawShapeZone`、`drawNet`、`drawStageNotice`、`drawPauseButton`、`drawPauseMenu`、`drawTitleScreen`、`drawInputSelect`)原樣保留, 函式名與 state 不變; `Art.layout` 不變

## 邏輯畫布尺寸

1280 × 720(`Art.canvas.width / height`)。所有座標皆為此邏輯解析度。

## 形狀語言

圓形為主、圓角面板; **能拿起來的東西(氣泡)是立體的球: 漸層 + 高光 + 落影; 地上的東西(內圈、染色區、賦形區、網)一律平塗、無影**; 有色 = 實心, 無色 = 空心灰白框; 地塊中央放說明效果的符號(水滴 = 染色、空心形狀 = 賦形); 亮著的網 = 網格 + 色框 + 同色外光, 不亮 = 細灰虛線空圈; 預告中 = 虛線; 新出場 / 剛改變 = 四個白色角框; 線環 = 單顆物件的事件, 填滿地面的亮光 = 全場事件(清場)。

## 理念落實

- P0 辨識度先於好看: 氣泡(立體球 + 落影 + 壽命環、半徑 20)、染色區(平色池 + 水滴、半徑 24)、賦形區(灰藍平地 + 空心形狀)、亮著的網(網格 + 色框 + 外光、半徑 60)、不亮槽位(細灰虛線空圈)五種長相各不同; 氣泡與地板的區分從 v10 的「有沒有一小塊高光」改成「立體 / 平面 + 有影 / 無影」, 氣泡壓在同色區域上時也看得出是球疊在地上(回應第 5 輪老闆回饋)。每種物件的每個狀態(冒出中 / 閒置 / 停留 / 按住 / 拖曳 / 彈回; 未出場 / 預告 / 出場提示 / 生效 / 縮小預告; 不亮 / 亮著 / 剛亮起)各有獨立外觀
- P1 視覺權重跟著決策迫切度: 全場最亮的是那一張亮著的網與氣泡; 氣泡的立體與高光讓「該抓的東西」比地板跳出一層; 7 個不亮槽位降到細灰虛線; 換位那一刻給最強的動態(掃光 + 角框); 清場回饋只在場上已經沒有氣泡、玩家沒有東西要決策的那一刻播, 1 秒內淡掉(下一批 1 秒內到), 不蓋住任何決策資訊
- P2 規則上存在的東西畫面上就存在: 不亮槽位畫成空圈; 預告中與縮小預告各有長相; 凍結(冰藍環)、彈回中不可按(半透明)、回命(那一格放大 + 白環)、已鎖定擦過(灰虛線環內收)都有外觀; 波次的每顆冒出都有演出(水紋 + 彈起), 一批依序冒出時看得出出場順序與陣型; 清場(加分 + 下一批提早來)有專屬回饋; 可抓的氣泡在滑鼠停留時浮起(可互動要被看見)
- P3 一個意義一種長相: 半透明只給「彈回中」, 預告一律用虛線; 灰白 clear 只代表「無色」(冒出水紋也是灰白: 剛冒出的氣泡一定是透明圓); 紅只代表危險 / 損失; 白角框只代表「剛出現 / 剛改變」; 往外擴的線環 = 單顆的屬性變了或被收下, 往內收的灰虛線環 = 沒變; 冒出演出刻意不用線環(用扁橢圓水紋 + 彈起), 清場刻意不用線環(用填滿地面的亮光), 避開字典裡已被佔用的長相; 立體 + 落影只給氣泡; 說明頁的網、槽位、氣泡、區域、命、結束畫面直接呼叫遊戲內畫法
- P4 關鍵區分至少兩條通道: 四色只靠色相 + 明度(老闆明言 prototype 不考慮色弱); 語意不同的東西走兩條通道: **可拿的氣泡 vs 地板(立體漸層 + 落影 vs 平塗無影, 另加壽命環)**、透明 vs 有色(空心 / 實心 + 色相)、亮著 vs 不亮、預告 vs 生效、凍結 vs 走動(環色 + 放大 / 影子)、捕捉(單點白環 + 勾)vs 清場(整片地面亮起 + 內圈邊光 + 中央字)、回命 vs 扣命、擦過生效 vs 已鎖定(線型 + 方向)
- P7 每個元素要掙得版面: 網只要顏色時中央不放符號; 不亮槽位不顯示條件; 氣泡上不放數字或「已鎖定」記號; 網與區域上不寫名稱字樣; 氣泡的新外觀全靠本體(漸層、高光、影子), 沒有加任何新標籤; 清場的「清空 +50」是全場唯一的事件字, 只在清場那 1 秒出現(拿掉測試: 只有地面亮光時, 玩家分不出「清空了」與「某種場地效果」; 規格要求一眼看出清空)
- P13 事件要排隊: 清場只會在場上沒有氣泡時發生, 同一刻不會有擦過回饋或拖曳; 捕捉當幀若同時清場, 勾在外圈槽位上、清場在內圈裡, 兩處不重疊; 場上只有一條預告文字與一條清場文字, 兩者位置不同(左上 HUD 下 / 內圈正中)
- P17 進度類資訊, 圖形與數字分工: 氣泡上沒有數字, 依邊界「沒有數字時圖形照舊畫總進度」, 壽命環畫 12 秒總剩餘比例; 預告的填色與預告條畫「離生效還多久」
- P18 重要資訊不能只存在一瞬間: 清場分在 HUD 分數裡常駐; 換位提示消失後亮著的網常駐; 扣命 / 回命閃光之後愛心常駐; 結束畫面再列存活時間與分數(清場次數依規格不顯示)
- P19 資訊貼著物件: 條件畫在網上; 壽命畫在氣泡上; 冒出演出畫在那顆氣泡的位置; 清場回饋畫在被清空的內圈本身; 預告與出場提示畫在那塊區域上
- P21 示意圖選分岔例子: 第 1 頁擦過色 A 再擦色 B 仍是色 A(分開「最後擦的覆蓋」); 第 2 頁透明放上亮網、色 A 放不亮槽位都回內圈且命仍 5 格; 第 3 頁兩種「之後」位置不同、一種同色一種換色; 第 4 頁兩顆環同起點, 只有按住的不走

## 物件表

所有函式簽章固定 `(ctx, state)`, 每個函式內部自行 save / restore。state 內沒寫預設值的欄位為必填。「未出場」的區域不呼叫; 不亮的槽位照樣呼叫(畫空槽)。

|---|---|---|---|
| 內圈外區域 | `drawBackground(ctx)` | 無 | 整面 bg 深色 |
| 內圈 | `drawInnerRing(ctx, state)` | 無(state 可省略) | 固定: 圓心 (640,360) 半徑 210 的亮一階平面圓 + 3px 邊線 |
| 染色區(染 A~D) | `drawPaintZone(ctx, state)` | `x, y`: 中心(用 `Art.layout.zones`); `color`: 0~3; `r`: 目前生效半徑(預設 24; 階段 5 縮小生效後傳 20); `status`: `'preview'`/`'on'`/`'shrink'`(預設 on); `previewT`: 預告進度 0→1(2 秒, 1 = 生效那一刻); `shrinkTo`: 縮小後半徑(預設 20); `introT`: 出場提示進度 0→1(生效後 2 秒; 0、≥ 1 或不傳 = 不畫) | 生效中: 平色池(該色 50% 填色 + 3px 實線色框)+ 中央白框水滴; 平塗、無漸層、無影。預告中: 色虛線框 + 由中心長大的淡色填色 + 虛線水滴。縮小預告中(`'shrink'`, `r` 仍傳 24): 生效外觀照舊 + 一圈白虛線從 24 往內收到 20。出場提示中: 生效外觀 + 四個白角框 |

不需要獨立函式的物件:
- 網條件: 只顯示在亮著的網上, 由 `drawNet` 的 `color` / `shape` 一起畫; 拆開 RD 要自己對位, 也容易在不亮槽位誤畫
- 氣泡壽命環: 畫在氣泡上, 由 `drawBubble` 的 `life` 一起畫
- 存活時間、分數、連續數: 都在 HUD 區, 由 `drawHud` 一起畫
- 氣泡的「冒出」: 不是另一種物件, 是氣泡的過渡狀態, 由 `drawBubble` 的 `spawnT` 畫(冒出那一刻起就是可按的一般氣泡, 拆成獨立函式 RD 得在演出期間換畫法再換回來)

### 與理念的張力(交製作人決定)

- 階段切換預告條的「場地即將改變」與各區域自己的預告外觀部分重述(P7)。保留理由: 區域預告外觀小, 拖曳中視線不一定看得到。試玩覺得多餘時不呼叫即可
- 換位掃光每次捕捉都播, 是全場最常出現的大動態(P8 候選)。試玩嫌吵可拿掉 `from`, 只留角框
- 「已鎖定」收縮灰環可能頻繁出現; 試玩嫌吵可改成不觸發 `'locked'`
- 清場回饋的「清空 +50」是遊戲中唯一的事件字樣。規格要求一眼看出清空; 若試玩覺得字多餘, 可只留地面亮光與邊光(需要時告訴美術, 改成參數)
- 波次冒出同時有 4~6 顆在彈, 每批都播(P8 候選「動得越多, 每個動作分到的注意力越少」)。保留理由: 規格要求冒出過程可辨識, 且一批依序冒出就是陣型的呈現; 演出 0.4 秒、只在出批的 0.8 秒內發生
